# 10 — Interface rework (last)

Done after workstreams 01–09b, because each of them adds entry points and the interface must be organised
around the final set, not the current one. The current interface is a sound base (owner's words): this is
a reorganisation and a finish, not a new product and not a new framework.

## Current state (verified)

- Plain TypeScript and DOM helpers (`src/ui/dom.ts`), one stylesheet (`src/styles.css`, about 1,400
  lines), the shell in `src/ui/App.ts` (about 1,700 lines) which builds the toolbar, the panels and the
  cards and also holds loading, exporting, selection and views logic.
- Two toolbar rows with around twenty controls of equal weight (Export GLB / USD, Open, Folder, Metadata,
  Samples, Measures, undo / redo, 2D, Visit, Map, Views, Sections, Frame, Hide, Isolate, Show all, GLB ↓,
  JSON ↓, Quick Look), a left column with three tabs (Tree, Colours and filters, Assistant), a right
  properties column, and the 4D planning at the bottom.
- Notices such as the "Revit file read" card overlay the 3D view and stay until closed.
- Workstream 01 lists what is dead or duplicated in the interface code; do that first.

## Direction

1. **One place per job.** Group by what the user is doing, not by when the feature was added:
   - *File*: open, add a model, samples, export (one menu: 3D file, properties, modifications, PDF, DXF, OBJ).
   - *Look*: views, sections, standard views, 2D / visit / map, frame, hide / isolate.
   - *Understand*: tree, properties, colours and filters, quantities, measures.
   - *Check*: compare, clashes, completeness.
   - *Plan*: 4D planning, zones.
   - *Ask*: the assistant as a command bar reachable from anywhere (keyboard shortcut), its history in a panel.
2. **A toolbar of what is used every minute**, the rest in menus and in a command palette that lists every
   action by name (the same list the assistant's layer 1 understands, so there is one catalogue of actions).
3. **Panels that dock and collapse** left, right and bottom, with remembered sizes; the 3D view always
   gets the remaining space. Nothing permanent floats over the model: notices become a status line and a
   notifications list.
4. **A consistent visual language**: one set of design tokens (spacing, radius, type scale, colours for
   states: selected, modified, added, removed, clash, warning), light and dark, used everywhere; the
   stylesheet split by component.
5. **Professional finish**: empty states that say what to do, progress with a cancel for every long job
   (IFC, Revit read, quantities, clash, print), errors that say what happened and what to do, focus
   visible, full keyboard use, labels on every icon button.

## How to run it

- Start from evidence: screenshots of every current screen and state at 1440, 1024 and 390 px, light and
  dark, with the problems written on them. Use the design skills available to the agents at that time
  (interface critique, accessibility review, front-end design) rather than taste alone.
- Decide the information architecture on paper (the six groups above, what goes in the toolbar) and get
  the owner's agreement on a clickable mock-up of the shell before touching the code.
- Then, in this order: tokens and stylesheet split → shell (toolbar, menus, docking) → each panel moved
  into the shell one at a time, behaviour unchanged → command palette → states (empty, loading, error) →
  narrow screens → accessibility pass → motion and polish.
- `App.ts` is split along the same lines as the shell (file, view state, selection, exports, panels
  registry) as part of this workstream; workstream 01 gives the list of responsibilities.

## Constraints

- No UI framework, no CSS framework, no icon font: plain TypeScript, the existing DOM helpers, inline SVG
  icons. Performance first: the interface must not cost frames while orbiting a large model.
- French interface text, short and plain; the vocabulary already used (« Arborescence », « Coupes »,
  « Cotes ») stays unless the owner changes it.
- Accessibility: WCAG 2.2 AA / RGAA as the bar (contrast, keyboard, names, focus order, reduced motion).
- Every existing feature stays reachable. The feature inventory in workstream 01 is the checklist: each
  line is ticked in the new interface before the old control is removed.
- The JSON contracts and `window.viewerBim` do not change because of the interface.

## Watch out for

- Tests that reach into the DOM or rely on control order.
- The built-in notices that carry important facts (elements hidden at opening, partial shapes, model
  truncated by the triangle budget) must stay visible somewhere obvious after they stop being a floating card.
- Docking and resizing must not trigger a full re-render of the tree on large models (220,000 elements).
- Map mode has its own canvas and controls; the shell must host both.
- Touch and narrow screens: decide what is supported (viewing, properties, views) and what is desktop-only
  (sketching, clash), and say it in the interface.

## Acceptance

- Every line of the feature inventory reachable in at most two actions from the shell or through the palette.
- No horizontal scroll and no overlap from 390 px to 2560 px.
- Keyboard-only walk-through: open a sample, select an element, change a property, save a view, export.
- Orbiting the 22,500-element sample with every panel open keeps the frame rate of today's build (measure
  before and after, pane in front).
- Automated checks: contrast of every token pair, focusable elements have names.
