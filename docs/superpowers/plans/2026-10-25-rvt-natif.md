# Native Revit (.rvt) reading — step 1 plan

Owner: Opus (design, review). Implementation: Sonnet subagents, one task each.
Branch: `feature/rvt-natif`. Nobody commits or pushes; the lead does that when the user asks.

## Goal

Open a `.rvt` in the viewer and display it natively, processed in the browser tab: no Revit, no
Autodesk service, no paid library, no IFC or GLB file in between, nothing uploaded. Performance is a
hard requirement (see "Performance" below). Step 1 covers Revit 2023–2027 project files fully;
2015–2022 files open with whatever rvt-rs reads (marked as such). Later steps (not now): files of
hundreds of MB (streaming, multi-worker), real shapes and parameters for 2017–2022, phases filters /
graphic overrides / saved 3D views / walk mode / `.rfa`.

## Decisions (final, do not re-open)

- Reader: **rvt-rs** (Apache-2.0, Rust) as a Cargo git dependency pinned to commit
  `0304c038c6d90fdf2b14e5ed47aea1d0e65e4997` (https://github.com/DrunkOnJava/rvt-rs), feature
  `unstable-research` (saved graphics, object graphs and parameters live there). Our own crate wraps
  it; we do not fork it. Anything missing is written in our crate on top of rvt-rs's public API
  (`ObjectGraph` etc.).
- Our crate: `revit/` at the repo root (like `pipeline/`, `worker/`). Plain Rust pipeline usable
  natively (tests, measurement) + a thin `wasm-bindgen` wrapper compiled for `wasm32-unknown-unknown`.
- Built wasm + JS glue are **committed** in `src/revit/pkg/` (the repo already commits binaries such as
  Draco), so `npm run dev`, `npm test` and CI need no Rust. `npm run
  build:revit` rebuilds them. Release profile: `opt-level = 3`, `lto = true`, `codegen-units = 1`,
  `panic = "abort"` is NOT allowed (keep unwinding off by default is fine, but panics must surface as
  errors: use a panic hook that reports the message).
- Geometry, per element, in this order (never silently a box):
  1. **Revit's saved display shape** (`rvt::research::native_saved_scene` — channel 103, includes the
     family type's shape placed by each instance, plus Revit's render material colours).
  2. **Rebuilt shape** from the element's Revit data (rvt-rs `IfcModel` bodies: walls, slabs, roofs,
     columns, beams, stairs, pipes, curtain parts, …), triangulated through rvt-rs's own glTF builder
     (`rvt::ifc::gltf::build_gltf`), excluding bodies whose `BodySource` is the record bounding box.
  3. **Box** from the element's bounding box, drawn, and marked unknown.
  Each element carries the property `Source de la géométrie` with one of:
  `Forme Revit`, `Forme Revit partielle` (some saved faces could not be tessellated),
  `Forme reconstruite`, `Inconnue (boîte englobante)`.
- Not drawn (as in a Revit 3D view and as the IFC converter does for `IfcSpace`): rooms, areas,
  spaces, levels, grids, reference planes, cameras/views, scope/section boxes, annotation
  categories. Elements with no geometry at all are counted in the report, not drawn.
- Identity key (`extras.id` equivalent, the link to metadata/planning JSON): the element's **IFC
  GlobalId as Revit's own IFC exporter computes it** (rvt-rs gives it), so a JSON written against an
  IFC export of the same model also links to the RVT. Fallback when unavailable: `rvt-<ElementId>`.
- Coordinates: Revit internal feet, Z up → metres, Y up: `(x, y, z)ft → (x, z, −y) × 0.3048`.
  Positions are emitted **relative to the model's centre** (computed in f64 in Rust) as f32, and the
  centre is returned as `origin` (metres, Y up, f64) so precision is kept far from the origin.
- Built-in parameter names: table generated from **Rhino.Inside.Revit** (MIT,
  https://github.com/mcneel/rhino.inside-revit, `src/RhinoInside.Revit.External/DB/Schemas/<year>/`
  `ParameterId.Enum.cs` + `ParameterId.Values.cs`, and `BuiltInCategory.cs`, `ParameterGroup.*.cs`):
  numeric id → enum name → ForgeTypeId. French labels are **our own wording** (Revit-FR-like for the
  common ones; a readable French rendering of the identifier for the rest). Attribution in
  `revit/THIRD_PARTY.md` and the repo `NOTICE`.
- UI language: French, like the rest of the app. Code comments: French, same density as nearby code.

## Output of the reader (the contract between Rust and TypeScript)

`read_revit(bytes: &[u8], options) -> Output`, exposed to JS by `wasm-bindgen` as `readRevit(bytes:
Uint8Array, options?: object)` returning a plain JS object:

```ts
interface RevitOutput {
  keys: string[];             // N elements, unique, see "Identity key"
  names: string[];            // N display names ("Famille : Type" or category name + id)
  sources: Uint8Array;        // N, 0 Forme Revit, 1 partielle, 2 reconstruite, 3 inconnue
  origin: [number, number, number]; // metres, Y up
  positions: Float32Array;    // xyz, metres, Y up, relative to origin
  normals: Float32Array;      // xyz unit vectors, one per vertex
  indices: Uint32Array;       // triangle corners, local to the primitive's first vertex
  primitives: Uint32Array;    // stride 6: element, vertexStart, vertexCount, indexStart, indexCount, material
  materials: Uint8Array;      // stride 6: r, g, b, a (sRGB bytes), transparent (0/1), doubleSided (0/1)
  metadata: string;           // JSON exactly per docs/contrat-metadonnees.md (version 1, readOnly, elements)
  report: {
    release: number | null;  // Revit year from BasicFileInfo
    experimental: boolean;    // rvt-rs support level for that year is experimental
    elements: number; triangles: number; seconds: number;
    sources: { revit: number; partial: number; rebuilt: number; unknown: number };
    withoutGeometry: number;  // elements found but with nothing to draw
    warnings: string[];       // French, user-facing
  };
}
```

Rules: triangles wind counter-clockwise seen from outside after the axis change (the change flips
handedness: check it). No duplicated triangles. Every primitive's indices < its vertexCount.
`metadata.elements[key]` exists for every key; `label` = names[i].

## Properties written in `metadata` (per element)

Top level: `Catégorie` (French category name), `Famille`, `Type`, `Niveau`, `Identifiant Revit`
(ElementId, number), `GUID IFC`, `Phase de création`, `Matériaux` (array of names),
`Source de la géométrie`. Then one nested object per Revit parameter group (French group name, e.g.
`Contraintes`, `Cotes`, `Données d'identification`, `Phase de construction`, `Autre`), holding every
parameter rvt-rs reads for the element: instance parameters, then type parameters (name suffixed
` (type)`), for **every** category including walls, floors, roofs, ceilings (join the type through
the element's type id). Values: text, number, boolean; ElementId values → the target's name;
length/area/volume/angle converted to SI with the unit in the name (`Hauteur non contrainte (m)`,
`Surface (m²)`, `Volume (m³)`, `Angle (°)`), rounded to 6 significant digits. Unnamed ids that are
not in the catalog: `Paramètre Revit <id>`. `readOnly` lists every top-level name and every group
name used (all Revit data is read-only, like IFC data). `georeference` when rvt-rs gives the site
location (see `src/geo/georeference.ts` for the shape).

## Performance

- Decode runs in a Web Worker; the main thread only wraps transferred typed arrays.
- Measured natively (M4 Pro): rvt-rs decodes 34 MB `2024_Core_Interior.rvt` in 2.4 s at ~850 MB
  peak RSS (~25× the file size); saved graphics add 0.3–1.6 s. Target in Chrome for that file:
  model visible in ≤ 5 s from drop, UI responsive throughout.
- wasm32 has 4 GiB per instance: refuse files above a limit derived from the measured memory ratio
  (French message pointing to the coming large-file support), and turn out-of-memory into a clear
  message, never a hang.
- The wasm module is downloaded only when the first `.rvt` is opened.

## Repo conventions (all tasks)

- exFAT drive: `npm install --no-bin-links`; run tools as `node node_modules/...` (see package.json).
  macOS may create `._*` files: never add them.
- `npm test` (node --test, Node 24, TypeScript run directly), `npm run build` (tsc + vite) must pass.
- Three.js only for display; no new runtime JS dependency.
- Keep `docs/contrat-metadonnees.md` compatible (it is a public interface).
- Never call the LLM in tests. Never commit or push.

## Tasks

1. **Scaffold** — crate, toolchain, wasm build script, samples script, stub pipeline returning a valid
   empty `RevitOutput` + real `report.release`, native `revit/examples/measure.rs`, Rust test, Node
   test loading the committed wasm, NOTICE/THIRD_PARTY.
2. **Geometry** (`revit/src/geometry/`) — saved shapes, rebuilt shapes, boxes, packing, axis change,
   origin; report counts; plus a census of saved faces that could not be tessellated, by surface class.
3. **Properties** (`revit/src/properties/`, `revit/src/catalog/`) — catalog generation from
   Rhino.Inside, French labels, all parameters, type joins, units, phases, categories, materials,
   georeference, metadata JSON.
4. **Engine raw input** (`src/engine/buildModel.ts`) — `buildModel` accepts a `RawModel` built from the
   typed arrays above, sharing the batching code; tests.
5. **Viewer integration** (`src/revit/`, `src/ui/App.ts`) — worker, lazy wasm, `.rvt` drop/open,
   progress, report, limits, downloads, README + `docs/lecture-revit.md`.
6. **Missing surface types** — tessellate the surface classes found missing by task 2's census.
7. **Verification** — all samples natively and in Chrome, timings, review.
